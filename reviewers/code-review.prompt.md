# コードレビュー（実験用の共通プロンプト）

あなたは Java / Spring Boot / MyBatis のシニアエンジニアとして、次のアプリケーションをレビューします。

- 対象: `{TARGET}`（ソース・テスト・設定・SQL・ビルド設定のすべて）
- 仕様の参考: `{SPEC}`（設計書。仕様との食い違いも指摘してよい）
- **ほかのフォルダ・リポジトリは読まない**（答えが書かれた資料があるため。読んだ場合は結果が無効になる）

## 観点

正しさ（異常系・境界・同時実行・トランザクション）、エラー応答の一貫性、運用（終了コード・ログ）、テストの抜け、規約・保守性。

## 出力

次の Markdown の表だけを `{OUTPUT}` に書く。指摘は最大 20 件、重要な順に。

| No | 重要度 | 箇所 | 指摘 | 根拠 |
|---|---|---|---|---|

- 重要度: MUST（直さないと不具合）/ WANT（直すべき）/ NITS（軽微）/ Q（質問）
- 箇所: ファイル名（必須）とメソッド名か行
- 指摘: 何が起きるかを具体的に（どんな入力・状況で、どうなるか）
- 根拠: コードのどこからそう言えるか。推測なら「推測」と書く
